# Brief — Lot 1 · la scène (le nouveau Round)

> **Pour l'instance d'intégration.** Ton monde = ce fichier + les specs sources
> citées (elles font foi). Stack : React Native / Expo managed, TypeScript. Le
> **domaine du lot 0 est fait et prouvé** (83 tests) — tu **branches l'UI dessus**,
> tu ne réécris aucune logique de score. À la fin : un diff + le résultat des tests
> + un mot sur la jouabilité, puis handoff propre.

## Intention

Le **premier lot qui touche l'écran** : bâtir le **nouveau Round** — l'écran de
jeu unique qui **absorbe** *nommer · jouer · saisir* en **états**, pas en écrans.
On pose la **scène** (cartouche + plateau + zone du bas) et le **battement** de
saisie. **Ossature, pas polish** (« factoriser n'est pas polir »).

## Périmètre — ce qui est DEDANS

### 1. `RoundScreen.tsx` [R] — la scène à 3 conteneurs
Trois zones empilées (cf. `specs-ecrans` §Le Round) :
- **le cartouche** (haut, fin, persistant) — la voix calme « {prénom} mène ».
- **le plateau** (~50 %, persistant) — 4 quadrants (pills) autour du disque
  central + la **flèche du sens de jeu** (`PlayDirection`, réintégrée).
- **la zone du bas** — conteneur à **hauteur dépendante de l'état** (voir §2).
- **États absorbés** : *nommer* (ex-Setup) · *jouer* (repos) · *saisir*
  (ex-ScoreEntry). Un seul écran, du 1er prénom au dernier point.
- Retirer l'alert « Rejouer avec qui ? » (le retour se fera par la nav en 3a —
  ici, un `resetGame`/`cancelGame` du store suffit, sans écran d'accueil).

### 2. La zone du bas — à hauteur d'état *(la contrainte que les rendus 70/30 ratent)*
| état | zone du bas | contrainte dure |
|---|---|---|
| **nommer** | le **clavier natif** monte, pills éditables sur le plateau | plateau (pills à nommer) **reste visible** au-dessus du clavier (~45-48 %) |
| **jouer** (repos) | **aperçu feuille minimal** : les 2 dernières manches + la ligne vierge | jamais une ligne orpheline ; zéro vide mort |
| **saisir** | le **numpad-calculette 3×4** | tient dans ~40 %, la pill active reste visible |

*(L'aperçu feuille ici est un **mini** running — PAS la feuille modale complète,
qui est lot 3b.)*

### 3. Le battement *(le cœur — cf. `reshape.md` §battement)*
`tap une pill` (seule cible) → elle **s'allume**, le **numpad monte** → le nombre
s'affiche **sur la pill** → ordre libre → **« = »** actif à **4/4** (exactement un
joueur à 0) → **calcul** (via le domaine lot 0 : `computeRoundScore`/`computeTotals`)
→ totaux mis à jour sur les pills. La ligne vierge de la feuille = **écho visuel,
pas un bouton**.

### 4. `PlayerPill.tsx` [R]
- **tap = saisie** de ce joueur ; **état allumé** quand active.
- La **notif « {prénom} donne sa meilleure carte »** (sur la pill du perdant de
  manche) — **gardée telle quelle** (validée par l'usage).
- ⚠️ **PAS le long-press renommer** (c'est lot 3a). Le long-press GOF de l'ancien
  code **disparaît** (le GOF vivra au Gong, lot 4).

### 5. `NumPad.tsx` [R]
Numpad-**calculette 3×4** : `0-9` · **del** · **« = »**. Le « = » **est** le
valider (déclenche le calcul), actif à 4/4 (un seul à 0). Pas d'auto-validation.

### 6. `Cartouche.tsx` [N]
La voix calme : une fine ligne persistante « {prénom} mène » (dérivé des totaux
courants). **Texte seul, change sans animation.** *(Les annonces éclatantes =
lot 2, PAS ici.)*

### 7. `theme/tokens.ts` [R] — placard **v1 ossature**
- Poser la **structure** placard : base **noir / crème**, aplats, zéro ombre
  décorative ; rôles typo (condensé-bold pour ce qui proclame, mono pour le
  chrome) en tokens.
- Les **4 couleurs de siège** : **gardées telles quelles** en placeholder (leur
  redesign est **lot 4**). **Zéro polish** (chaleurs 4d/4f, matières = lot 4).

### 8. keepAwake *(friction n°1 soirée 01)*
L'écran **ne se verrouille pas** pendant une partie en cours ; se relâche hors
partie. Via `expo-keep-awake` (API JS `activateKeepAwakeAsync`/`deactivate…`).
**Vérifie s'il est déjà dispo** (dépendance Expo courante) ; s'il faut l'ajouter et
qu'un rebuild natif est requis, **signale-le** (le build est porté par une instance
dédiée — tu ne déclenches pas de build EAS).

### 9. `App.tsx` — **stopgap de lancement** *(temporaire, borné)*
Pour que le nouveau Round soit **jouable et testable** : fais ouvrir l'app
**directement sur le nouveau Round** (Splash → Round ; le Round gère *nommer*
lui-même). **Ne construis PAS** le hub-and-spoke ni l'accueil — c'est **lot 3a**.
Laisse `SetupScreen`/`ScoreEntryScreen`/`ScoreGridScreen`/`Hub` **sur le disque**,
simplement **non routés** (ils meurent en 3a). Marque ce changement « stopgap lot 1 ».

## Definition of done = LA GATE

**Une partie complète est jouable au doigt sur le nouveau Round** : nommer les 4 →
jouer des manches → saisir via le numpad (« = ») → les totaux montent sur les
pills, l'aperçu running est lisible → jusqu'à ce qu'un joueur passe 100 (le
domaine détecte `isGameOver` ; le **rendu du final est lot 2** — ici, l'état
terminé suffit, sans cérémonie). **L'écran ne se verrouille jamais** pendant la
partie. `tsc` clean. **Les 83 tests du lot 0 restent verts.**

*(Lot UI : la preuve est surtout **manuelle sur device**. Ajoute des tests de
composant/smoke si c'est peu coûteux, mais ne casse aucun test existant.)*
